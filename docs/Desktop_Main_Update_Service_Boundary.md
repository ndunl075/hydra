# Electron main update service boundary

The pinned Code - OSS Windows service is replaced at its `IUpdateService` registration point with Hydra's own Electron-main implementation. Hydra does not construct the upstream Win32 updater, so its cache recovery, arbitrary package path, and installer launch paths are unavailable. The patch uses exact source matches and fails during `desktop:prepare` if the pinned registration changes.

The service uses installed trust and the main-owned profile path. When enabled in a future signed release, a check fetches only the fixed stable channel record, verifies its Ed25519 signature and target against the clock after fetching, and commits the candidate and monotonic sequence in the durable journal before reporting `AvailableForDownload`. A saved available candidate is reauthenticated after restart; a later phase requires review rather than another fetch. The service still refuses download, apply, quit-and-install, external package, and internal-channel commands. The next increment must add main-owned download confirmation and native artifact verification before an install action can appear. The distributed product record still has `hydraUpdateTrust.status: "disabled"` and no upstream `updateUrl`.
