# Delegation context ingress

Feature 22 provides the host boundary for a child that explicitly asks for missing context. The caller first uses `viewDelegationContextRequest` to show the request as **pending**. Viewing parses only the bounded receipt; it does not read sources, write a journal record, start a process, submit a model request, or claim that context was supplied.

The host invokes `ingressDelegationContextRequest` only after an explicit user action. It revalidates the parent ID, run ID, child key, authorized read scope, and the exact source path, revision, and SHA-256 digest. It then appends the immutable request to the Feature 07 orchestration journal. The result is either selected source references (`id`, path, revision, SHA-256) or a concise refusal for an invalid/out-of-scope request, an oversized delivery request, or a changed/missing/substituted source.

The pure ingress accepts host-observed source identities so it can be tested without filesystem access. Production host wiring uses `DelegationIngressHost`: the caller supplies only a child task ID and opaque request, and the adapter derives the parent/run/child binding and scopes from saved records. A manifest SHA-256 covers a recorded excerpt rather than the whole file. The host checks that hash, reads the bounded Git blob at the child base commit and literal source path, verifies that it contains the excerpt, and requires the current worktree file to match the blob byte for byte. It also checks checkout identity, refuses unsaved child editor buffers before and after observation, and rejects missing, redirected, changed, oversized, non-UTF-8, or unverifiable sources with `stale-source`. This conservative rule may refuse a source after an unrelated edit to its file. It does not copy source content into the receipt or invoke a model.

The Feature 07 journal persists both the immutable request and its first selected/refused outcome. Replay after restart returns that durable outcome without recalculating a source decision. Concurrent observations also return whichever outcome was first persisted. The request is journal-idempotent by its request key, so the same exact request does not create another receipt; a changed request using that key returns a bounded `conflict` refusal and leaves the prior receipt intact.

`hydra.recordDelegationContextRequest` accepts a child ID and sealed request, verifies that each requested identity matches the saved child manifest, and stores a pending inbox entry without reading source files or invoking a provider. The selected child's inbox then allows the person to explicitly supply the request; that webview action sends only the request key and the host loads the saved receipt. `DelegationIngressHost.supplyContext` remains internal, with no public supply command. A selected receipt is an observation-time decision and must be revalidated before later source delivery.
