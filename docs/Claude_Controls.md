# Verified Claude settings and scoped approvals

Hydra 0.17.0 adds a candidate adapter for the official Claude Code 2.1.270 CLI. It initializes streaming input and reads provider-applied model/effort before submitting the task prompt. It uses the CLI's existing login and environment; no Agent SDK runtime, API key substitution, account mutation, or settings-file write is introduced. Authenticated edit/test/approval/interruption/resume acceptance is still pending an agreed live-test budget.

## Model and effort

Open **Model and effort** on a Claude task, load models, choose an advertised model and explicitly choose its effort, then save. Metadata discovery disables customizations and tools, uses no session persistence, and submits only `initialize` and `get_binary_version`. It creates no user turn, reads no history, and returns only bounded model metadata. The CLI's catalog is not account entitlement or quota proof. A model without explicit supported efforts or a canonical identity cannot be saved as an override. The public catalog has no default-effort field; Hydra does not invent one.

Selections lock before queue submission with the task brief. An explicitly configured task runs through Hydra's managed route; terminals and official-extension handoffs cannot acknowledge the selection and are refused. Once acknowledged, its canonical model identity is pinned in Hydra-owned turn history; a later change in the provider's alias resolution refuses resume before the prompt and requires a new task to accept the new identity. With no saved selection, Hydra sends no model or effort flag.

Each first or resumed invocation uses the recorded native `--resume` ID when applicable and the task's exact working directory. Before sending a `user` frame, it reads `initialize`, checks `get_binary_version` and the default/manual permission mode, reloads the catalog, and queries `get_settings`. The provider's `applied.model` and `applied.effort` must exist; `null` effort means no effort parameter. For a saved choice, effective model must match its newly advertised canonical identity and effort must match exactly. Organization caps, environment overrides, unavailable metadata and mismatched settings prevent the prompt. Requested and effective values are saved separately before the user frame, with cancellation, schedule, budget and resource-readiness guards rechecked after durable saves.

`system/init` still validates CLI version, working directory, permission mode and native UUID identity. For an explicit selection its model must also match the acknowledgement. A mismatch stops the owned process and marks an error; it sends no corrective turn. Initialization can arrive after the provider has begun handling the prompt, so this later check cannot guarantee no internal request already ran. Effective settings describe the next root request; they do not guarantee the model/effort of every internal call or nested agent. Real resumed-session acceptance remains separate from fixture evidence.

## Approval boundary

The CLI is launched with `--permission-prompts host`. Hydra handles main-session `can_use_tool` requests only for Bash/PowerShell and Edit/Write/MultiEdit. The card shows the original input and provider reason. **Allow this request** echoes that input and tool-use ID; **Decline** returns a deny response. No suggested permission rule or `updatedPermissions` is sent, no session-wide allowance is inferred, and the input is not edited behind the user's consent. Existing provider rules/hooks may already permit tools without prompting; Hydra does not claim to intercept every tool call or impose a sandbox.

Interactive dialog tools, MCP/network/unknown tools, subagent requests, and requests requiring their own local interaction stop the turn with official-client guidance. Duplicate/malformed requests and oversized details receive no permission grant. Provider cancellation removes the card; completed, stopped, cancelled or previously answered requests cannot be approved. Stop terminates only Hydra's owned process tree and awaits closure; graceful provider interruption is not claimed.

Framing allows at most 1 MiB per line; total turn stdout/stderr is bounded to 32 MiB. Control correlation is strict, outstanding requests time out at 15 seconds, pending approvals are bounded to 20, and at most 1,000 provider request IDs are accepted per turn. Metadata discovery has a 2 MiB output limit and a 20-second deadline. Settings/account response payloads are excluded from raw logs; effective model/effort and control correlation are retained separately. Other task/provider events remain local diagnostics.

## Pinned public evidence

The declaration-only reference comes from the official [`@anthropic-ai/claude-agent-sdk@0.3.270` package](https://www.npmjs.com/package/@anthropic-ai/claude-agent-sdk/v/0.3.270), SHA-512 integrity `sSfcm5Nhb+WHeBCxqeHRRQMUKPmFTL+zgv5xcRUVaFMLttfNEbn3IZJE+fLJJmy4h3J8zdc5sXdSa1JxyB8ppQ==`. Only declarations and its manifest were extracted; no SDK JavaScript or bundled CLI was executed. Relevant declarations are ModelInfo, SDKControlRequest/Response, get_settings, PermissionResult, can_use_tool and SDKUserMessage.

The declarations describe optional `system/init.effort` on bridge hosts, with the same effective value as `get_settings.applied.effort`. Hydra therefore queries settings instead of assuming every init frame publishes effort. A no-prompt, tools/customizations-disabled, nonpersistent probe of the installed CLI 2.1.270 on 17 September 2026 returned catalog metadata and effective model/effort and exited zero. This proves the local read-only contract, not authenticated model access, normal customization behavior, native resume, editing or real approval acceptance. [Official model configuration](https://code.claude.com/docs/en/model-config) explains effort precedence and policy caps; [programmatic CLI use](https://code.claude.com/docs/en/headless) documents the provider-owned CLI boundary.

All 133 final local regression tests passed, as did type checking, the build and four final isolated native fixture hosts. Fixtures cover metadata-only discovery, explicit alias/canonical matching and pinning, first/resumed settings, missing acknowledgement, caps, unsafe modes, version/correlation mismatch, cancellation during handshake, bounded framing, exact command/file consent, stale decisions, provider cancellation, unsupported interactions and restart persistence. Native hosts additionally exercise real extension commands, scheduler approval state and reload recovery. Browser fixtures verify explicit effort selection, exact save/allow/decline dispatch and locked settings in dark/light modes. No fixture contacts a model.

The implemented metadata client also read the installed official CLI's catalog. The implemented managed adapter then completed initialize/version/settings against that CLI with tools/customizations and persistence disabled; its mandatory second launch guard stopped before any user frame. It reported zero submitted model turns, clean owned process closure and no cleanup errors. That verification did not resume a session or exercise actual tools. Native acceptance stages the candidate extension over a copied verified 0.14.0 editor baseline; it is not a full source-built 0.17.0 release. Full revision CI and the broader manual/release gates remain required.
