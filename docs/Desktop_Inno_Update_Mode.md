# Hydra installer update mode and version guard

The Windows user installer now has a Hydra-specific `/HYDRAUPDATE=1` mode. It requires silent setup and `/NORESTART`, refuses upstream `/UPDATE`, positive close/restart switches, task overrides, and loaded answer files. The mode requires an existing registered per-user Hydra installation at the selected destination and a strictly newer stable `major.minor.patch` release. Normal installs use the same equal-version/downgrade guard; same-version repair is not yet supported. An unregistered existing destination or mismatched registration refuses instead of being overwritten.

The pinned Inno transformation is drift-checked in `scripts/desktop.mjs`, and the additional Pascal code lives in `desktop/hydra-update-mode.iss`. Setup no longer force-closes applications or restarts them. Hydra update mode checks the app and tunnel mutexes and returns before the pinned script can stop processes or services. It also skips installer-driven app launch and updater garbage collection. Existing task choices, including the optional desktop shortcut, are loaded from Inno's prior install state; update mode refuses task overrides and does not delete an existing shortcut.

The disposable Windows installer lifecycle now checks selected and unselected fresh installs and equal-version refusal. The distinct-version fixture installs the pinned old release, exercises update-mode switch refusal, upgrades to the current release with both shortcut states, and checks equal-version refusal. A synthetic newer registry version checks this installer's downgrade guard; historical installers do not gain a guard retroactively. No updater service invokes this mode yet. The native helper, authenticated consent/journal handoff, signing policy, and signed release acceptance remain separate gates.
