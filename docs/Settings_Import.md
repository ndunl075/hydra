# Settings import

In the local standalone Hydra app, open **Hydra: Open Settings → Import preferences**. **From VS Code** detects `%APPDATA%/Code/User`; **From Cursor** detects `%APPDATA%/Cursor/User`. **Choose profile folder** accepts the User folder or a specific profile folder containing `settings.json`, `keybindings.json`, and/or `snippets`. Portable/custom installations use the picker.

Preview performs no writes to preferences. Choose Settings, Keybindings, and/or Snippets, then click **Import selected preferences**. The preview shows additions, preserved conflicts, and skips without exposing setting values. It shows up to 500 item rows; category totals include all entries. Backups are written before preference changes.

Hydra's own desktop command returns the active profile's exact resources, including any resources inherited from Default. Preview warns when importing a category will change preferences shared with Default. The importer does not infer destinations from extension global storage, which belongs to Default. Named profiles are supported; another profile's unshared preferences remain untouched. Remote windows and the VS Code development host cannot import.

Settings and snippets merge with JSONC edits, preserving destination comments. Existing keys win, including inside language-specific settings. Existing user key/chord bindings win conservatively even when incoming conditions differ; casing and repeated spaces do not bypass conflict detection. New bindings append in source order. Unknown settings and unavailable color themes are skipped, preserving the current theme. Missing keybinding commands and snippet languages are shown as dependency warnings; this feature installs no extensions. Credential preferences/arguments are excluded, and only the three preference categories are read. Tokens, databases, histories, MCP/task configuration, and extension binaries are not copied.

Malformed JSON, duplicate/reserved keys, invalid UTF-8, invalid binding/snippet shapes, linked paths, source/destination overlap, dirty preference documents, and stale previews refuse with an error. Import limits are 1 MB per file, 10 MB of input, 100 snippet files, and 5,000 preview entries. Preview again after source or destination changes.

**Undo last import** restores exact original bytes or removes files created by that import. It checks every affected file before restoring: if preferences were edited afterward, undo refuses and retains the backup. Failed imports attempt safe rollback. Interrupted imports/undo keep a journal and show recovery status on reopening Settings; undo can resume when files still match the imported or original bytes. A cross-window lock serializes imports across the same Hydra user-data root. It does not promise filesystem transactions against arbitrary external writers; newer detected edits are preserved.

Backups are retained under Hydra's own extension storage, `globalStorage/nico-dunlap.hydra-agent-manager/preference-imports/<profile-resource-hash>/`. `latest.json` identifies the last journal; each journal records allowed destination paths and base64 original bytes. Keep these private as user preferences may contain sensitive existing data. If newer edits prevent undo, inspect the retained originals instead of replacing current files blindly. Old journals remain available; the UI undoes only the latest import.

Tests cover real preference files, named/default profiles, byte-exact restart undo, category selection, credential exclusions, unchanged source files, malformed inputs, junction boundaries, stale/dirty refusal, concurrent import locking, backup-path validation, automatic rollback, and interrupted undo recovery. Desktop acceptance exercises the native profile bridge, importing into an actual named profile, native configuration reload, unsaved-file refusal, and undo. Native CI must pass before merge; manual visual/accessibility acceptance remains pending. Opening Settings or importing preferences submits no model request.

This feature supplies the reusable import flow for subsequent skippable onboarding; it does not claim that onboarding or installer delivery is complete.
