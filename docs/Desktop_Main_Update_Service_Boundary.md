# Electron main update service boundary

The pinned Code - OSS Windows service is replaced at its `IUpdateService` registration point with Hydra's own Electron-main implementation. Hydra does not construct the upstream Win32 updater, so its cache recovery, arbitrary package path, and installer launch paths are unavailable. The patch uses exact source matches and fails during `desktop:prepare` if the pinned registration changes.

The service uses installed trust and the main-owned profile path. When enabled in a future signed release, a check fetches only the fixed stable channel record, verifies its Ed25519 signature and target against the clock after fetching, and commits the candidate and monotonic sequence in the durable journal before reporting `AvailableForDownload`. A saved available candidate is reauthenticated after restart; a later phase requires review rather than another fetch.

The Download action now reauthenticates the journal-bound candidate, asks for confirmation in an Electron-main native dialog, and reauthenticates again after the user responds. Cancellation leaves the operation available without creating a staging file. Confirmation commits `downloading` before the UI reports a download, network starts, or a file is created; only the immutable installed origin and journal UUID reach the bounded staging primitive. A matching SHA-256 leaves the operation in `downloading`, not an install-ready state. The service still refuses apply, quit-and-install, external package, and internal-channel commands. Native publisher verification, shutdown consent, and helper launch remain separate gates. The distributed product record still has `hydraUpdateTrust.status: "disabled"` and no upstream `updateUrl`.
