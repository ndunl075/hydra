# Windows user installer

After `desktop:build` and `desktop:smoke`, run `npm.cmd run desktop:installer` on native Windows x64. This packages the verified standalone app using the pinned upstream Inno Setup user-installer task. It produces `.desktop/code-oss/.build/win32-x64/user-setup/HydraSetup.exe`. The bundled module and product version must match the current Hydra manifest, preventing accidentally packaging a stale runtime.

The installer uses Hydra's isolated application/registry identities and logo. Installer versioning follows Hydra's module version; the editor API remains at its upstream version for extension compatibility. The artifact is currently unsigned. Code signing, release distribution, and automatic updates are not configured by this milestone.

**Create a desktop shortcut** remains unchecked on a fresh install. Inno remembers prior task selections during reinstall. An explicit opt-out removes Hydra's previous desktop shortcut; background updates retain existing shortcuts. The standard visible installer offers launch afterward. Tests suppress launching the app, file associations, and PATH changes.

The Windows desktop CI job generates the installer only after native desktop acceptance. `scripts/desktop-installer-test.ps1` refuses execution outside a disposable GitHub-hosted Windows runner. It checks fresh default-off behavior, opted-in shortcut target, remembered selection on reinstall, explicit opt-out, and uninstall cleanup. Sentinel files prove Hydra preferences/extensions, VS Code and Cursor preferences, and an unrelated project survive. Existing Hydra registration/shortcut causes refusal rather than replacement. Logs and successful installer artifacts are retained for seven days.

The original lifecycle gate tests same-version reinstalls. A distinct-version upgrade gate is now prepared in `scripts/desktop-upgrade-test.ps1`, with live CI acceptance still pending. It refuses execution outside disposable GitHub-hosted Windows runners and never tests a developer's installed profile.

`desktop/upgrade-baseline.json` pins the successfully tested Hydra 0.13.0 Windows run, exact source head, immutable installer artifact ID/digest and installer SHA-256. CI verifies run/artifact provenance before downloading with read-only Actions access; the script verifies the installer file hash before execution. An expired or mismatched baseline fails the gate rather than selecting an unverified replacement. CI artifacts expire after seven days; explicitly revalidate the baseline when necessary.

The new gate requires a strictly newer current Hydra version. It tests separate prior-install/upgrade/uninstall cycles with both selected and unselected desktop shortcuts, verifies remembered selection and shortcut target, and checks product/module/registry version identity. Executable and bundled-module bytes must match the exact current CI build. The pinned Inno task adds `target: "user"` to `product.json` before packaging; the gate verifies that this is the only semantic change from the built product and that the installed product matches the staged installer input byte-for-byte. Hashed sentinels cover Hydra settings, a named profile, task metadata, extensions, VS Code/Cursor preferences and an unrelated project. Logs and provenance are uploaded even on failure. Syntax and local refusal checks do not establish upgrade success; the disposable Windows run must pass before this gate is marked accepted. Visible wizard/launch-after-install acceptance and signing remain outstanding.

The commands and task-selection behavior follow the [official Inno Setup command-line documentation](https://jrsoftware.org/ishelp/topic_setupcmdline.htm) and [uninstaller documentation](https://jrsoftware.org/ishelp/topic_uninstcmdline.htm).
Cross-run artifact download inputs follow the [pinned official download-artifact v4 action](https://github.com/actions/download-artifact/blob/v4/action.yml).
