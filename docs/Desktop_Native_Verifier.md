# Native update verifier primitive

`native/desktop-update-verifier.cpp` is the first implementation increment of [Windows update-channel slice 4](Desktop_Update_Channel_ADR.md). It accepts a caller-owned Windows file handle held without write or delete sharing, signed SHA-256 and byte length, and an installed signer subject and certificate thumbprint. It refuses directory/reparse/multiple-link files, mismatched bytes, a nonzero `WinVerifyTrust` result, missing or ambiguous provider signer information, and a signer that differs from the allowlist. It extracts the signer from the successful trust provider state rather than treating an arbitrary certificate in the file as proof. The SHA-1 thumbprint identifies the allowlisted certificate; the signed artifact digest remains SHA-256.

The current verifier requests whole-chain revocation checking, chain checks excluding the root, and lifetime signing. It does not yet prove the release owner's final timestamp and revocation policy, PE product/version, installation identity, or ancestor-handle protection. The test-only `desktop-update-verifier-fixture.cpp` accepts caller paths and trust values solely to exercise the primitive; it must never be packaged. `scripts/desktop-native-verifier-test.ps1` compiles it with the Windows x64 toolchain and uses a currently valid signed browser executable to exercise accepted, wrong-signer, wrong-length/hash, unsigned, and tampered cases. This fixture does not stand in for a Hydra-signed release or controlled revoked/timestamped certificates.

There is no installed native helper or process-launch path in this increment. A later reviewed increment must derive paths from a durable operation ID, hold staging ancestors and installer handles against replacement, validate exact Hydra PE identity, independently authenticate handoff and consent, and refuse uncertain recovery. Installer execution stays disabled until the Inno update mode and main-process consent/journal slices also pass their gates.
