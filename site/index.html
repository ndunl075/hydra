Know what your agents did before you merge.

Hydra is an IDE that runs Claude Code and Codex tasks in parallel. Each task gets its own git worktree and branch. You watch, review, and commit from one window, and nothing touches your checkout until you say so.

View on GitHub Build Hydra.exe

Hydra makes a worktree for every task, checked out at committed HEAD on a unique branch. Your agent works there, alone. Dirty edits in your main checkout stay exactly where they are. When the task stops, you read the diff in a native editor tab, stage what you want, and commit the tree you reviewed. Not the tree the agent last touched.

Whether the change came from Claude Code, from Codex, or from you handing a task off to the official extension, the record of what happened is local, timestamped, and survives reload.

$ hydra: new task "Rewrite the retry loop in worktree.ts" → branch agent/retry-loop-3f2a → worktree ../hydra-worktrees/retry-loop-3f2a (from HEAD 4054229) → provider codex 0.154.0 sandbox ready … approval run: npm test [allow once] [allow for task] [deny] … stopped 3 files changed, 41 insertions, 12 deletions → review base-to-saved · staged · unstaged · untracked → commit reviewed tree 9c1e0b7 recorded

How it works

  1. Start a task, not a chat.

    Give it a title and a brief. Hydra creates the branch and worktree, reserves ports and service names if you asked for them, and runs your setup commands in the checkout. Setup must pass before any provider work launches.

  2. The agent runs in its own checkout.

    Managed Claude and Codex sessions stream into the task view: text, raw events, token usage, and scoped approval cards for commands, files, and network. You can interrupt a turn or stop the whole process tree. Or open the provider in a native terminal at the exact worktree and drive it yourself.

  3. Run several at once, within a limit you set.

    The default is two active sessions per window. Extra launches wait in a persistent queue with explicit dependencies. Soft budgets can warn or hold new work based on reported usage. The agent map shows every repository, worktree, and running session on one canvas.

  4. Review the diff. Commit the tree you read.

    Stopped tasks open in read-only native diff tabs: base-to-saved, committed, staged, unstaged, untracked. Prepare a commit review to freeze a tree, then commit exactly that tree. Stale changes, active writers, and unsaved buffers refuse. Your Git hooks still run.

  5. Hand off when it makes sense.

    An idle or stopped task can open in the official Claude Code or Codex extension, in a separate window with only that checkout and the task prompt. Login, permissions, and conversation history stay with the provider.

What is in the box

One worktree per task
Isolated files and index for every agent. No shared working copy, no half-applied edits across tasks, and no automatic copying of secrets, ignored files, or dependencies.
Editor and Agents in one window
Toggle between a normal editor layout and the agent manager with one keystroke. Task selection, session output, approvals, and follow-up drafts are shared between both modes.
Native review
Renames keep both paths. Deletions compare against an empty side. Binary, large, non-UTF-8, and submodule changes show metadata instead of a fake text diff.
Provider usage in view
Refresh Codex account limits without spending a model turn. Missing fields stay missing, observations are timestamped, and stale data is labelled stale.
Local, versioned records
Tasks, sessions, and receipts are stored with atomic, versioned metadata. Corrupt records are kept for diagnosis rather than silently dropped.
A standalone editor
Hydra ships as Hydra.exe, a Windows x64 build with the Hydra module built in. VS Code is a development test host, not a dependency of the product.

What Hydra does not do

Worth knowing before you rely on it.

It does not talk to models itself.

Hydra never sends a prompt on its own. Opening a task, switching modes, or refreshing usage never submits a provider request. Authentication lives in the official CLI or extension.

It does not merge for you.

A reviewed commit is a local receipt. Integrating into your target branch is a separate, explicit step.

Worktrees are not a sandbox.

They isolate files and indexes. They do not contain a process. Codex sandbox readiness is checked before a turn, but that is the provider's sandbox, not Hydra's.

It does not promise background survival.

Hydra stops the terminals it owns when the extension shuts down. A session that goes missing is marked interrupted, never completed.

Get it running

Windows x64, Node.js 22, and the official Claude Code or Codex CLI installed with its own login.

PS> npm.cmd ci PS> npm.cmd run desktop:build PS> npm.cmd run desktop:verify PS> npm.cmd run desktop:smoke # build lands in .desktop/VSCode-win32-x64/
