# Auto delegation brief

`prepareAutoDelegationBrief` produces the initial child display/dispatch prompt from a host-owned `ChildContext`, a `ContextPolicy`, receipt proposals, and a host-owned `AutoDelegationBriefAuthority` passed separately from the model-controllable input. A receipt binds its ID, path, full revision, SHA-256, kind, and durable approval receipt to the selected evidence. It is only a claim until `authority.verifySourceReceipt` validates it against host durable state or a host signing key. A model-created self-consistent receipt, including a positive-looking approval value, cannot authorize a source. The host integration owns the verifier and must fail closed when verification fails or throws. It calls `buildChildContext`, so the resulting prompt retains the task, repository and user constraints, base commit, write scope, dependencies, acceptance criteria, source provenance, and provider settings already required by the delegation context contract.

The input has no transcript field. Only evidence with matching host approval receipts is supplied to `buildChildContext`; repository instructions and agreed interfaces remain mandatory. The builder is deterministic and pure: it does not read files, access credentials, create a worktree, or submit a provider turn. It refuses known credential/transcript forms as defense in depth and refuses an over-limit brief rather than truncating mandatory requirements. The approval receipt is the trust boundary; text matching is not relied on to classify unknown content.

Before an existing dispatch path uses the prompt, it must call `assertAutoDelegationBriefFresh` or `dispatchAutoDelegationBrief` with the current host-observed source revisions and hashes plus the same host authority. These functions revalidate every receipt, verify the sealed brief, and delegate source freshness to `assertFreshContext`; a missing, stale, or unverified source requires a new brief. `dispatchAutoDelegationBrief` returns only the already-verified prompt and has no provider or process side effect.

This is a Wave A contract only. It does not schedule a child, materialize a worktree, or attach to a host or UI path.
