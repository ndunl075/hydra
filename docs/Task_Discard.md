# Confirmed task discard and recovery

> **Removed (2026-09-24).** This described part of Hydra's managed-task system, which was removed once the Agents view became a live canvas of Hydra heads (see [Agents_View_Plan.md](Agents_View_Plan.md), "As built", and [Heads.md](Heads.md)). Kept for history; none of it is in the product any more.

Use **Review discard** after stopping a task's writers. Hydra lists commits absent from the recorded target branch and staged, unstaged and untracked saved changes. **Discard task…** opens a native confirmation identifying the title, branch, checkout and counts. Cancelling leaves the task unchanged. A changed task HEAD, target commit, index or saved tracked/untracked content requires a fresh review.

Discard retires the task record and removes it from normal task filters, the agent map and the native task tree. The complete checkout stays at its existing path. Its Git branch, staged state, untracked and ignored files, provider history, handoff notes and integration candidates are retained. This reversible action consumes no model tokens and starts no provider process. It does not reclaim disk space or permanently remove Git worktrees/branches.

Select **Discarded** to inspect the retained path and historical discard receipt. **Copy retained checkout path** supports manual inspection. **Restore task** verifies the original checkout/repository/branch identity, then returns an interrupted task. It never automatically launches a writer or accepts manually edited files as reviewed. Inspect the checkout, refresh review and explicitly choose a launch or follow-up when ready.

Live terminal/managed writers, externally owned sessions, queued or blocked requests, uncertain restart reservations, unsaved task buffers and tasks still referenced by another active task's dependency configuration refuse discard. Stop or reconcile ownership, save/revert buffers, cancel requests and remove dependencies explicitly first. Unrelated dirty main-checkout edits remain in place. Existing integration operations must finish or be cancelled before discard.

Discard reviews are transient and expire on reload; confirmations use only the currently prepared token. Durable records require a valid receipt and no active request or uncertain writer. Atomic-save failures leave the in-memory task unchanged. Concurrent unrelated session persistence waits for discard/restore before saving its updated task snapshot. Restart preserves discarded status, including when a retained checkout has since been removed manually. Restore refuses an unavailable or replaced checkout with retained diagnostics.

Review is bounded to 1,000 saved changed files, 1,000 unmerged commits, 64 MiB of untracked content and the existing Git output cap. Sparse/hidden index entries and task submodules require manual recovery; the checkout is preserved. Ignored files are retained and excluded from the review fingerprint. Unsaved buffers are never discarded. Hydra cannot observe manually launched processes outside its ownership controls.

Validation includes real-Git dirty/staged/untracked/ignored preservation, unchanged branch/index and dirty target, same-length untracked edits, moved task/target commits, writer/dependency refusal, failed saves, durable reload, explicit restoration and blocked writer interfaces. Native host smoke checks unsaved-buffer refusal, exact saved inventory, expired token refusal and unchanged provider request logs. Browser checks cover dispatch, archived filtering and blocked states. Full native modal/keyboard and manual recovery acceptance remain separate checks; fixtures do not establish live-provider acceptance.
