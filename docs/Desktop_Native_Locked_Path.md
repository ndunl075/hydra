# Native staged-file lease

`native/desktop-update-locked-path.cpp` is another bounded slice-4 primitive. It accepts a canonical Windows drive-letter user-data directory and a lower-case version-4 operation UUID, then derives only `hydra-updater/<operation ID>/HydraSetup.exe`. It opens each ancestor from the volume root with reparse-point refusal and retains handles without delete sharing. It opens the installer with read sharing only, refuses a reparse point or multiple hard links, and keeps all handles in one move-only lease. The verifier in [Desktop_Native_Verifier.md](Desktop_Native_Verifier.md) can consume that file handle and path without closing the lease. The caller must retain the lease through any later process creation; no launch path exists yet.

The caller-supplied user-data root is a **test seam**, not production authority. The future installed helper must derive the current Hydra profile location itself, bind it to the installation identity, and accept only the durable operation ID from its trusted handoff. `scripts/desktop-native-locked-path-test.ps1` compiles a test-only caller and exercises valid operation lookup, traversal/noncanonical IDs, a hard link, a junction, and attempted directory rename and installer write while the lease is held. The Windows desktop workflow runs this fixture before the full build.

This does not authenticate a journal entry, prove consent, inspect Hydra PE identity, validate release-owner signing policy, or permit installer execution. Those remain required before slice 4 and the later update-service slices can be accepted.
