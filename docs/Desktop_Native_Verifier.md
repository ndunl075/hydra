# Native update verifier primitive

`native/desktop-update-verifier.cpp` is the first implementation increment of [Windows update-channel slice 4](Desktop_Update_Channel_ADR.md). It accepts a caller-owned Windows file handle held without write or delete sharing, signed SHA-256 and byte length, and an installed signer subject and certificate thumbprint. It refuses directory/reparse/multiple-link files, mismatched bytes, a nonzero `WinVerifyTrust` result, missing or ambiguous provider signer information, and a signer that differs from the allowlist. It extracts the signer from the successful trust provider state rather than treating an arbitrary certificate in the file as proof. The SHA-1 thumbprint identifies the allowlisted certificate; the signed artifact digest remains SHA-256.

The verifier requests whole-chain revocation checking, chain checks excluding the root, and lifetime signing. It now independently requires the verified leaf certificate to be valid at the current system time and to carry an explicit code-signing EKU. It calls `WTD_STATEACTION_CLOSE` after every `WTD_STATEACTION_VERIFY`, including a trust refusal without a state handle. A timestamp cannot rescue an expired leaf under this conservative first-channel policy. Revoked, offline, unknown, and all other nonzero `WinVerifyTrust` results refuse. [Microsoft's WinTrust state and lifetime-signing contract](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/ns-wintrust-wintrust_data) defines these actions and flags.

`scripts/desktop-native-verifier-test.ps1` compiles a test-only policy fixture that injects trust outcomes to check refusal, missing signer state, policy flags, and exactly-once cleanup, then uses a currently valid signed browser executable to exercise actual Authenticode acceptance, wrong signer, wrong length/hash, unsigned, tampered, and multiply linked files. Neither fixture is packaged. Injected revoked/expired/offline statuses establish fail-closed branching, **not** end-to-end acceptance of controlled revoked or timestamped Hydra certificates. The latter, a release-owner timestamp/renewal decision, PE product/version, installation identity, and ancestor-handle protection remain release gates. `WTD_UI_NONE` suppresses UI but supplies no verification deadline; the eventual helper supervisor must bound its wait without turning timeout into acceptance.

There is no installed native helper or process-launch path in this increment. A later reviewed increment must derive paths from a durable operation ID, hold staging ancestors and installer handles against replacement, validate exact Hydra PE identity, independently authenticate handoff and consent, and refuse uncertain recovery. Installer execution stays disabled until the Inno update mode and main-process consent/journal slices also pass their gates.
