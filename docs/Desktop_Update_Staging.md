# Desktop update download and staging boundary

`src/core/desktopUpdateStaging.ts` implements delivery slice 3 of the [Windows update channel decision](Desktop_Update_Channel_ADR.md). It fetches the untrusted envelope only from `/channels/stable/win32-x64/user.json` beneath the installed HTTPS origin, with a 96 KiB response cap and 30-second deadline. The caller must pass those bytes to `verifyDesktopSignedUpdate` before using any payload field.

For the artifact, the module accepts only a `VerifiedDesktopUpdate` produced by that verifier and the installed origin. It derives `/artifacts/sha256/<signed digest>/HydraSetup.exe`; metadata cannot choose a URL or redirect destination. The production transport is Node HTTPS with ordinary certificate validation. Non-200 responses, including redirects, refuse. A ten-minute deadline and 1 GiB artifact ceiling bound the transfer. Streamed bytes must match both the signed length and SHA-256; an incorrect `Content-Length` refuses before writing.

The main process must provide its own absolute, canonical user-data directory. Staging creates `hydra-updater/<random operation ID>` with exclusive creation, restrictive Windows ACLs (current user, SYSTEM, Administrators) or Unix owner-only permissions, a free-space margin, and reparse-point checks. It refuses an existing staging root instead of silently reusing a cached installer. Failures and cancellation remove the operation it just created. `verifyStagedDesktopUpdateArtifact` reopens an operation by its validated ID and refuses changed size, type, or content before later native checks. The success return is evidence for the next gate, not install authorization.

The channel remains disabled in `desktop/product.json`. No main-process updater invokes this module yet. The native helper in slice 4 must independently verify the actual file and Authenticode signature and hold it against replacement through installer launch; slice 6 owns the durable operation journal, cache lifecycle, consent, and recovery. These later gates cannot rely on this module's in-process hash alone.
